# Conclusion

A language-model agent can convert an owned VulnHub-style OVA into a Docker replica only if the conversion is a procedure with a score, not a single build that happens to answer HTTP. The procedure in this project is six skills. The agent imports one appliance onto an existing NAT network, recovers local administration from a powered-off clone, repairs end-of-life apt under stated limits, inventories the guest without recording secrets, builds one container from that inventory, and scores the container on eleven parity rows. The skills are generic so the same order can be applied to another owned appliance. When a conversion exposes a trap, the trap is written back into the skill. The next agent reads the correction instead of spending another session on it.

That is why the skills matter more than the finished Dockerfile. The Dockerfile is the outcome of one appliance. The skill is the rule that made the outcome legal, and the rule that tells the agent when a confident result is still a partial score. Haynes et al. (2009) supply the checklist form. Yao et al. (2023) supply the contrast: a plan generated inside one episode does not survive into the next OVA. Jimenez et al. (2024) supply the scoring instinct. Success is a completed check. Here the check is parity, and a shared kernel is not allowed to become a pass (Boettiger, 2015).

On this appliance the evaluation shows the quality difference directly. Table 2 and Figure 2 count it: five passes and six partials before the rules were in the skills, and eleven passes afterward. Table 3 names the fix for each partial row. Before the rules were in the skills, the replica ran and the page answered, but package versions, the database engine, listeners, cron, mail, and the application URL were partial: Debian 9 and MariaDB stood in for Debian 8 and MySQL 5.5, `rpc.statd` and the php5 cron snippet were missing, and the stored URL had been rewritten. After the procedure was applied, the parity report marked all eleven rows pass, including the guest package strings, MySQL 5.5.60, Sendmail on 127.0.0.1:25 and :587, and `http://raven.local/wordpress/`. Archive apt with `trusted=yes`, the WSL kernel `6.18.40.1` in place of guest kernel `3.16.0-6-amd64`, and supervisord in place of sysv init stayed in the gap list. That is the result the procedure is for. A smaller container that hides those gaps would be a worse result, not a better one (Felter et al., 2015; Nüst et al., 2020).

The speed difference is the iterations the next agent does not repeat. The session observed a wrong-suite image and short Sendmail probes before the skills stated the Jessie base, the MySQL package, `sendmail -bD`, and the one-minute scoring window. A scripted search found all 23 coded rules in the skills and one of them in the finished replica files. The lookup medians, 1.014 milliseconds and 143.469 milliseconds, only show that the rules are in the skills and are not recoverable from the replica files. They are not model latency. A second agent was not timed, so this paper does not claim a numeric speedup. It claims that the procedure tells the next agent which checks to run and which results to reject, and that the evaluation of the conversion is the parity report those checks produce.
